# API Endpoints

## Обзор

Сервис предоставляет REST API для управления переговорными комнатами, бронированиями и пользователями.

Полная спецификация API доступна в следующих форматах:

* **Swagger UI** - `http://localhost:8080/docs`
* **ReDoc** - `http://localhost:8080/redoc`
* **OpenAPI Specification** - `openapi.json` (расположен в корне репозитория)

Файл [`openapi.json`](docs/api/openapi.json) содержит полное описание всех доступных эндпоинтов, моделей запросов и ответов, параметров, схем аутентификации и возможных кодов ответа.

---

## Аутентификация

Все защищённые эндпоинты используют JWT Bearer Token.

| Метод | Endpoint               | Описание                                      |
| ----- | ---------------------- | --------------------------------------------- |
| POST  | `/auth/tokens`         | Получение пары JWT-токенов по логину и паролю |
| POST  | `/auth/tokens/refresh` | Обновление access-токена                      |
| POST  | `/auth/tokens/revoke`  | Отзыв refresh-токена                          |

---

## Комнаты

Эндпоинты для управления переговорными комнатами.

| Метод  | Endpoint                            | Доступ           | Описание                                      |
| ------ | ----------------------------------- | ---------------- | --------------------------------------------- |
| GET    | `/rooms`                            | Все пользователи | Получить список переговорных комнат           |
| GET    | `/rooms?date={date}&available=true` | Все пользователи | Получить доступность комнат на указанную дату |
| POST   | `/rooms`                            | Admin            | Создать новую комнату                         |
| PATCH  | `/rooms/{room_id}`                  | Admin            | Обновить информацию о комнате                 |
| DELETE | `/rooms/{room_id}`                  | Admin            | Удалить комнату                               |

---

## Бронирования

Эндпоинты для управления бронированиями.

| Метод  | Endpoint                         | Доступ           | Описание                                                                       |
| ------ | -------------------------------- | ---------------- | ------------------------------------------------------------------------------ |
| GET    | `/reservations`                  | Все пользователи | Получить список бронирований (свои - для сотрудника, все - для администратора) |
| POST   | `/reservations`                  | Все пользователи        | Создать бронирование (себе - для сотрудника, любому - для администратора)                                                          |
| PATCH  | `/reservations/{reservation_id}` | Все пользователи        | Изменить параметры существующего бронирования  (своего - для сотрудника, любого - для администратора)                                |
| DELETE | `/reservations/{reservation_id}` | Все пользователи | Отменить бронирование (своё - любой пользователь, любое - администратор)       |

---

## Пользователи

Эндпоинты для управления пользователями. Доступны только администраторам.

| Метод  | Endpoint           | Описание                      |
| ------ | ------------------ | ----------------------------- |
| GET    | `/users`           | Получить список пользователей |
| POST   | `/users`           | Создать пользователя          |
| PATCH  | `/users/{user_id}` | Обновить данные пользователя  |
| DELETE | `/users/{user_id}` | Удалить пользователя          |

---

## Pydantic-схемы

Для валидации входных данных и формирования ответов используются Pydantic-модели.

Основные группы схем:

* **Authentication** - получение и обновление JWT-токенов.
* **Room** - создание, обновление и получение информации о переговорных комнатах.
* **Reservation** - создание, изменение и получение бронирований.
* **User** - создание, обновление и получение информации о пользователях.

Полный перечень моделей с их полями и ограничениями приведён в `openapi.json` и доступен через Swagger UI.
