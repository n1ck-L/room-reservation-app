## О проекте

Веб-сервис бронирования переговорных комнат для коворкинга. Сервис представляет собой REST API (см. [Документация](#документация)), реализованный на фреймворке FastAPI с использованием PostgreSQL для хранения данных и JWT-аутентификации.

#### Система включает следующие сущности:
- *Комнаты* - переговорные комнаты с заранее определёнными временными слотами.
- *Бронирования* - информация о занятых временных слотах для конкретной комнаты и даты.
- *Сотрудники* - могут просматривать доступность комнат, создавать бронирования, при этом, изменять и отменять только свои бронирования.
- *Администраторы* - обладают всеми возможностями сотрудников, а также могут отменять любые бронирования, управлять созданием сотрудников и комнат.

**Аутентификация** пользователей реализована с использованием JWT-токенов с ограниченным сроком действия.


## Требования

Для запуска сервиса на компьютере необходимо следующее программное обеспечение.

#### Обязательные компоненты
- **Python** версии **3.11** или выше.
- **PostgreSQL** версии **13** и выше.
- **Poetry** - менеджер зависимостей для Python. Все зависимости проекта устанавливаются и управляются через Poetry.
- **Git** - для клонирования репозитория.

#### Компоненты для запуска
В зависимости от выбранного способа запуска могут потребоваться дополнительные инструменты:
- **Uvicorn** - если приложение запускается напрямую с помощью ASGI-сервера (uvicorn).
- **Docker** - для запуска приложения в контейнере.
- **Docker** Compose - для одновременного запуска приложения и контейнера с PostgreSQL.

## Быстрый запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/n1ck-L/room-reservation-app.git

cd room-reservation-app
```

### 2. Установка зависимостей
Все зависимости проекта управляются с помощью Poetry.
```bash
poetry install
```

### 3. Настройка переменных окружения
Переменные окрудения берутся из файлы `.env`. В репозитории он расположен в корне проекта. По аналогии с примером из репозитория необходимо внести собственные данные (при необходимости).

Пример измененного содержимого:
```bash
# PostgreSQL
DATABASE_URL=postgresql://postgres:password@localhost:15432/reservation-app-db
DATABASE_PASS=password
DATABASE_USR=postgres

# JWT
JWT_SECRET_KEY=secret-token
JWT_REFRESH_SECRET_KEY=secret-token
```

### 4. Запуск и управление

Приложение поддерживает несколько способов запуска, что позволяет использовать его как для локальной разработки, так и для контейнеризированного развертывания.

**Предпочтительным способом запуска является Docker Compose** (см. [Docker Compose](#запуск-через-docker-compose)), так как он автоматически поднимает все необходимые сервисы (приложение и PostgreSQL), настраивает их взаимодействие и не требует дополнительной ручной конфигурации.

При необходимости приложение также можно запустить:
- через **Uvicorn** - для локальной разработки (см. [Uvicorn](#запуск-через-uvicorn))
- через **Poetry** - с использованием менеджера зависимостей проекта (см. [Poetry](#запуск-через-poetry))
- через **Docker** - с ручным запуском контейнеров приложения и базы данных (см. [Docker](#запуск-через-docker))

Ниже приведены **инструкции для каждого из способов** запуска.

#### Запуск через Uvicorn
1. Запустите контейнер с PostgreSQL:
```bash
docker run -d --name reservation-app-db -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=password -e POSTGRES_DB=reservation-app-db -p 15432:5432 -v pgdata:/var/lib/postgresql/data postgres:16-alpine
```
2. Запустите приложение:
```bash
uvicorn app.main:app --port 8080
```

#### Запуск через Poetry
1. Запустите контейнер с PostgreSQL:
```bash
docker run -d --name reservation-app-db -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=password -e POSTGRES_DB=reservation-app-db -p 15432:5432 -v pgdata:/var/lib/postgresql/data postgres:16-alpine
```
2. Запустите приложение:
```bash
poetry run uvicorn app.main:app --port 8080
```

#### Запуск через Docker
1. Создайте Docker-сеть:
```bash
docker network create reservation-net
```
2. Запустите контейнер с PostgreSQL:
```bash
docker run -d --name reservation-app-db -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=password -e POSTGRES_DB=reservation-app-db -p 15432:5432 -v pgdata:/var/lib/postgresql/data postgres:16-alpine
```
3. Соберите образ приложения:
```bash
docker build -t reservation-app -f dockerfile/Dockerfile .
```
4. Запустите контейнер приложения:
```bash
docker run -d --name reservation-app --network reservation-net --env-file .env -e DATABASE_URL=postgresql://postgres:password@reservation-app-db:5432/reservation-app-db -p 8080:8000 reservation-app
```

#### Запуск через Docker Compose

Запуск всех сервисов:
```bash
docker compose up -d --build
```
Остановка контейнеров:
```bash
docker compose stop
```
Полная остановка и удаление контейнеров:
```bash
docker compose down
```

### 5. Проверка работы
После запуска приложение будет доступно по адресу:
- **API**: http://localhost:8080
- Документация **Swagger**: http://localhost:8080/docs
- Документация **ReDoc**: http://localhost:8080/redoc

### Тестовая учетная запись

Для проверки работы API в проекте предусмотрена **учетная запись администратора**, которая создается автоматически при инициализации базы данных.

Используйте следующие учетные данные, которые при желании можно изменить в `.env`:

| Параметр | Значение |
| -------- | -------- |
| Логин    | `admin`  |
| Пароль   | `admin`  |

В Swagger UI нажмите кнопку **Authorize**, выполните аутентификацию через эндпоинт получения JWT-токенов (`POST /auth/tokens`), после чего используйте полученный `access_token` для выполнения защищенных запросов.

## Примеры использования

После запуска приложения открыть Swagger UI:

```
http://localhost:8080/docs
```

### 1. Получение JWT-токенов

Для авторизации используйте тестовую учетную запись администратора:

| Поле   | Значение |
| ------ | -------- |
| Логин  | `admin`  |
| Пароль | `admin`  |

Выполните запрос **POST `/auth/tokens`**, указав учетные данные администратора.

**Пример запроса**

```json id="rxxy8r"
{
  "login": "admin",
  "password": "admin"
}
```

В случае успешной аутентификации сервис вернет пару JWT-токенов.

**Пример ответа**

```json id="yj6zbw"
{
  "access_token": "<JWT_ACCESS_TOKEN>",
  "refresh_token": "<JWT_REFRESH_TOKEN>",
  "token_type": "bearer"
}
```

После успешной авторизации все защищенные эндпоинты станут доступны для выполнения.

### 3. Выполнение защищенного запроса

После авторизации выполните запрос:

```
GET /users
```

Так как используется учетная запись администратора, сервис вернет список зарегистрированных пользователей.

**Пример ответа**

```json id="ebxgq7"
[
  {
    "id": 1,
    "email": "test@example.ru",
    "login": "test",
    "password: "*******",
    "role": employee
  },
  {
    "id": 1,
    "email": "test@example.ru",
    "login": "test",
    "password: "*******",
```

### 4. Работа с остальными эндпоинтами

После авторизации аналогичным образом можно протестировать остальные возможности сервиса:
